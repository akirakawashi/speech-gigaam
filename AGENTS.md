# Правила работы с speech-gigaam

## Назначение

- Служба распознавания GigaAM v3 e2e RNN-T на GPU-сервере. Решение владельца
  14.10.2026: GigaAM поднимается отдельной службой в своём контейнере; воркер стоит
  на той же машине и шлёт в неё скачанные записи параллельными запросами.
- Служба только распознаёт: файл на вход, реплики с таймкодами на выход. Очереди
  заданий, хранения, ролей «оператор / клиент», LLM и записи в базу здесь нет.
  Что обработано, а что нет, учитывает вызывающий по ответу на свой запрос.
- Папка будет перенесена владельцем в отдельный репозиторий. Проект собирается
  самостоятельно, без импорта кода соседних проектов и стенда `temptest`.

## Архитектура и код

- Слои как в остальных `speech-*`: `src/domain`, `src/application`,
  `src/infrastructure`, `src/presentation`, `src/setting`, `src/di`.
  Domain не зависит от библиотек; application не импортирует infrastructure.
- Python 3.12, Pydantic 2, Pydantic Settings, строгая типизация. Русские
  докстринги: действие, вход, выход, ошибки, побочные эффекты.
- Логика распознавания перенесена со стенда `temptest` без изменений: поиск речи
  Silero, признаки с окном и мел-фильтрами из весов модели, жадный декодер,
  сборка слов. Не меняем её без сверки со стендом: главный критерий — текст службы
  совпадает со стендом слово в слово на тех же записях и том же движке.
- Версии `av`, `onnxruntime`, `silero-vad`, `torch`, `torchaudio` закреплены как
  на стенде. Смена любой из них — только со сверкой (`tools/compare_with_stand.py`).
- PyTorch ставится CPU-сборкой: видеокарта нужна только Triton. CUDA в образ службы
  не добавляем.
- Параллельность — процессы пула (`spawn`), не потоки. Модели загружаются в процессе
  один раз. Код, который передаётся в процессы, лежит на верхнем уровне модуля.
- Первая версия — урезанный режим. Голоса (CAM++) и эмоции (GigaAM-Emo) не
  добавляем без решения владельца; если добавим — модели загружаются один раз,
  а не в каждом обработчике.
- Текст разговоров в журнал не пишем: только размеры, длительности, время, счётчики.

## Окружение и проверки

- UV: `pyproject.toml`, `uv.lock`, сборщик `uv_build`. Установка —
  `uv sync --locked`, команды — `uv run --locked`. requirements-файлов нет.
- После изменения кода: `ruff format --check`, `ruff check`, `mypy src tests tools`,
  `pytest`. Проверяем сборку образа.
- Видеокарту на ПК и на сервере занимает только владелец: команды для прогонов с
  Triton готовим и отдаём ему, сами не запускаем. Локально цепочку можно проверить
  с энкодером ONNX на процессоре — см. [разработку](docs/development.md).
- Образ Triton не скачивается (`pull_policy: never`): реестр NVIDIA отвечает 403,
  образ переносится на сервер вручную.
