# Развёртывание speech-gigaam

## Что нужно на сервере

1. **Docker с доступом к видеокарте** (NVIDIA Container Toolkit). На GPU-сервере это
   уже работает: стенд `temptest` запускал Triton так же.
2. **Образ Triton `nvcr.io/nvidia/tritonserver:25.06-py3` в локальном Docker.**
   Напрямую реестр NVIDIA отвечает 403, поэтому образ переносится вручную и compose
   его не скачивает (`pull_policy: never`). Проверка:
   `docker image inspect nvcr.io/nvidia/tritonserver:25.06-py3 >/dev/null && echo есть`.
   Файл образа храните: если образ удалят из Docker, его возвращает
   `docker load -i <файл>`.
3. **Папка модели**, собранная под эту видеокарту: сейчас это
   `benchmark-cache/gigaam-trt` стенда `temptest` на сервере ([модель](model.md)).
4. **Сборка образа службы** тянет пакеты из PyPI и PyTorch CPU с
   `download.pytorch.org`, базовый образ — `python:3.12-slim-bookworm` с Docker Hub.
   Если с сервера это недоступно, образ собирается на другой машине и переносится
   так же, как Triton: `docker save speech-gigaam:0.1.0 | gzip > speech-gigaam.tar.gz`,
   на сервере — `docker load -i speech-gigaam.tar.gz`.

## Запуск

```bash
cd speech-gigaam
cp .env.example .env          # GIGAAM_MODEL_DIR — путь к папке модели на сервере
docker compose up -d --build  # без --build, если образ перенесён готовым
docker compose ps             # оба контейнера healthy
curl -s http://127.0.0.1:8090/ready
```

Служба стартует после того, как Triton загрузил модель. Сама она готова, когда все
обработчики загрузили модели и прогнали пробный фрагмент — обычно секунды.
Ошибка в папке модели останавливает службу до открытия порта; причина — в
`docker compose logs gigaam`.

Остановка — `docker compose down`. Обновление после правок кода —
`docker compose up -d --build gigaam`; Triton при этом не перезапускается.

## Ресурсы

По замерам стенда (урезанный режим, H100, 3 878 записей):

- **Процессор — главный ресурс.** На видеокарте только энкодер; поиск речи, признаки
  и декодер считаются на процессоре. На стенде — 2 ядра на поток, 10 потоков на
  20 ядрах. Отсюда `GIGAAM_CPUS ≈ 2 × GIGAAM_WORKERS`.
- **Память** — около 1,2 ГиБ на обработчик плюс звук обрабатываемой записи
  (около 6 МБ на минуту звука). `GIGAAM_MEMORY` с запасом: 1,5–2 ГиБ на обработчик.
- **Видеопамять** — около 0,5 ГБ на копию энкодера. На стенде урезанный режим добавил
  к занятой памяти карты около 1,5 ГиБ.
- **Копии энкодера в Triton** задаются в `repository/gigaam_encoder/config.pbtxt`
  (`instance_group … count`): на стенде — одна копия на каждые 5 потоков. После
  правки — перезапуск Triton (`docker compose restart triton`).

Скорость на стенде: 10 потоков прошли 146 ч звука за 13,5 мин, хотя клиент
перезапускался на каждую запись. Служба не перезапускает обработчики, поэтому должна
быть быстрее; сколько именно — покажет замер ([разработка](development.md#нагрузка)).

## Безопасность

- Порт службы открыт только на `127.0.0.1`: воркер стоит на той же машине.
  Порты Triton наружу не публикуются, он виден только службе во внутренней сети.
- Оба контейнера — без root (`10001:10001`), только для чтения, без привилегий;
  папка модели подключена только для чтения.
- Аутентификации у API нет: доступ ограничен машиной. Если службу откроют в сеть —
  нужен прокси с проверкой доступа.
- Текст разговоров в журнал не пишется.
