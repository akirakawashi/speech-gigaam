# API speech-gigaam

Порт службы внутри контейнера — 8000; compose публикует его только на этой машине
(`127.0.0.1:${GIGAAM_PORT}`, по умолчанию 8090). Описание OpenAPI — `/docs`.

## POST /v1/transcriptions

Тело запроса — сам файл записи, `Content-Type: application/octet-stream`. Формат —
любой, который читает FFmpeg (mp3, wav, ogg, opus, m4a, flac…). Заголовок
`X-Request-Id` необязателен и попадает в журнал службы.

```bash
curl -s --data-binary @call.mp3 -H 'Content-Type: application/octet-stream' \
     http://127.0.0.1:8090/v1/transcriptions
```

Ответ 200:

```json
{
  "engine": "gigaam",
  "model_name": "v3_e2e_rnnt",
  "model_digest": "<SHA256 весов>",
  "engine_digest": "<SHA256 движка TensorRT>",
  "language": "ru",
  "duration_s": 199.174,
  "source_channels": 2,
  "pcm_sha256": "<SHA256 моно PCM 16 бит 16 кГц>",
  "speech_segments": 41,
  "skipped_short": 0,
  "replies": [
    {
      "seq": 0, "start_ms": 1664, "end_ms": 6624,
      "text": "Здравствуйте, компания «Волна». Меня зовут Руслан. Чем могу вам помочь?",
      "words": [{"text": "Здравствуйте,", "start_ms": 1744, "end_ms": 2264}],
      "channels_db": [-24.1, -41.7]
    }
  ],
  "pauses": [{"start_ms": 0, "end_ms": 1764}],
  "processing_ms": 412,
  "wait_ms": 0
}
```

- **Реплика** — фрагмент речи от детектора с распознанным текстом. Границы
  включают короткие поля тишины по краям (до 0,1 с), как на стенде. В урезанном
  режиме в одну реплику могут попасть слова обоих собеседников, если между ними
  не было паузы.
- **`seq`** идёт подряд с нуля. Фрагменты, где модель не нашла ни букв, ни цифр,
  репликой не становятся; они учтены в `speech_segments`.
- **`words`** — время каждого слова от начала записи. Конец слова — начало
  следующего, но не дольше 0,6 с после последнего звука слова.
- **`channels_db`** — громкость каждого канала исходного файла на отрезке реплики,
  дБ относительно полной шкалы; тишина — −120. Для моно — `null`. Какой канал чей,
  служба не решает.
- **`pauses`** — промежутки, которые детектор не отнёс к речи, включая начало и
  конец записи.
- **`pcm_sha256`** — контрольная сумма декодированного звука; совпадает с
  `sha256_pcm` стенда для того же файла.
- **`processing_ms`** — обработка в обработчике; **`wait_ms`** — ожидание
  свободного обработчика.
- Запись без речи — тоже 200: пустой `replies` и одна пауза на всю запись.

Поля `engine`, `model_name`, `model_digest`, `language`, `duration_s` и реплики
(`seq`, `start_ms`, `end_ms`, `text`) соответствуют контракту приёма распознавания
бэкенда; роль реплики служба не заполняет.

## Ошибки

Тело ошибки: `{"error": {"code": "...", "message": "..."}}`.

| Код | HTTP | Что значит | Что делать вызывающему |
|---|---|---|---|
| `bad_audio` | 422 | не звук, нет звуковой дорожки, пустой файл | не повторять, задание — в ошибку |
| `audio_too_long` | 413 | запись длиннее `GIGAAM_MAX_AUDIO_SECONDS` | не повторять |
| `file_too_large` | 413 | файл больше `GIGAAM_MAX_UPLOAD_MB` | не повторять |
| `busy` | 503 | все обработчики заняты, очередь полна | повторить после `Retry-After` |
| `not_ready` | 503 | обработчики загружаются или служба останавливается | повторить после `Retry-After` |
| `timeout` | 504 | запись не уложилась в `GIGAAM_REQUEST_TIMEOUT_S` | повторить позже |
| `engine_failed` | 502 | сбой Triton или модели | повторить позже |
| `worker_failed` | 500 | обработчик упал, он уже перезапущен | повторить |
| `internal` | 500 | ошибка в коде службы | повторить; при повторении — разбирать журнал |

Правила для вызывающего, чтобы не терять записи:

1. Задание закрывать и свою копию файла удалять только после ответа 200 и передачи
   результата дальше.
2. На 503, 5xx, обрыв соединения и таймаут — повторять, а не пропускать. Повтор
   безопасен: служба ничего не хранит, результат тот же.
3. Параллельных запросов держать не больше `GIGAAM_WORKERS + GIGAAM_QUEUE_LIMIT`;
   проще всего — ровно `GIGAAM_WORKERS`.
4. Таймаут ожидания ответа — минуты, а не секунды: к обработке добавляется очередь.

## GET /ready

200 — все обработчики загрузили модели и Triton отвечает; иначе 503. Тело:

```json
{"status": "ready", "workers": 4, "alive": 4, "busy": 1, "waiting": 0, "capacity": 8, "triton": true}
```

`busy` — обработчики с записью, `waiting` — запросы в очереди, `capacity` — сколько
запросов служба принимает одновременно.

## GET /health

200 `{"status": "ok"}`, пока HTTP-процесс жив.

## GET /v1/model

Какая модель отвечает: `model_name`, `model_digest`, `engine_digest`, версия TensorRT.
